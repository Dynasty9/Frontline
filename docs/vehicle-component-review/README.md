# Vehicle component review

Reviewed all **143 rendered subjects** from front and rear: 135 model/alias keys, five parked civilian bodies and three wrecks. The table records what was changed or deliberately retained for every subject. Shared construction does not mean every vehicle received a new silhouette.

The most visible changes are individual track shoes, detailed spares and correctly fitted parked-car windows. Many running tyres were already rounded in the baseline; extracting those into the library is primarily a maintenance improvement. Aircraft canopies, ship hulls and vehicle-specific armour still have their own builders. These remain stylised procedural RTS models, not photorealistic assets.

Before is main at `70519054f7bec00757c35744891eb663ee6ebc80`; after geometry is `1c66227dda12d09d88ee614792efa6288ffc830e`. Captures use Godot 4.6.3, seed 3, a fixed studio, the same per-model framing rule and Compatibility renderer. Rear direction is (-1, 0.65, 1.25), front (1, 0.65, -1.25). The project targets Godot 4.7; local validation used the available 4.6.3 executable. No lighting or material-map edits were made for these comparisons. Very small framing changes can follow changed geometry bounds.

## Validation and remaining limits

- Component tests cover non-animated spares, axle orientation, one pivot per road wheel, outward-facing track pads for either outline winding, finite bounds and zero-length frame members.
- Roster material tests cover both palettes, shared texture assignments, glass distance fallbacks and wrecks; existing wheel motion, weapon sockets and distance-LOD tests pass.
- Roster (10 s), tank (30 s) and naval (10 s) fixed-step scenarios ran without script errors. The roster process reports two resources still in use during shutdown; this is recorded rather than treated as a clean shutdown diagnostic.
- Track shoes are static, as the old belts were. Full moving-track simulation, per-vehicle damage, bespoke hollow fighter cockpits and replacement parked-car bodies are outside this component pass.
- More near-detail geometry is baked into existing moving-part/material meshes and their distant fallback. This is not a measured performance improvement.

See [component authoring guide](../vehicle-components.md) for APIs, coordinate conventions and migration guidance. Capture commands and image hashes are in [capture.json](capture.json).
